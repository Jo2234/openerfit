# Deploy on Render Free

The public portfolio demo is [openerfit.onrender.com](https://openerfit.onrender.com). Record actual hosted results and known limits in the GitHub release for the exact deployed SHA. The repository includes a Node 24 Dockerfile and an optional `render.yaml` Blueprint. The image installs the full dependency set because the production server uses `tsx`, then builds and serves the frontend with the API.

The portfolio release uses one manually deployed Free Docker web service from the public MIT repository. Use the existing account; verify the actual workspace and shared Free usage before creating it. Confirm no payment method, paid trial, paid add-ons or automatic paid overage, and verify the current suspension/build-spend controls against the dashboard and [Render documentation](https://render.com/docs/free). The Free label alone is not evidence of zero spend.

1. In the verified workspace, create one Docker Web Service named `openerfit` from the reviewed public release branch. Set the instance to Free, with auto-deploy and previews off. Do not add disks, databases or paid monitoring. Keep unrelated existing services unchanged.
2. Set `QLOO_MODE=live` and the approved Qloo API host. Enter `QLOO_API_KEY` only in the service’s private environment settings, after its destination and access are authorized. Keep credentials out of Git, command arguments, browser code and screenshots.
3. Set every Groq override in [README](../README.md#environment), including `LLM_MODE=openai-compatible`, reasoning `none`, seed off, timeout 45000 ms and caps 512/512/768. Enter the existing `LLM_API_KEY` privately. The optional Blueprint defaults to `LLM_MODE=none`; creating it without overrides does not produce real-model behavior.
4. Use ephemeral `/tmp/qloo-cache`. For uncached acceptance set `QLOO_CACHE=off`. The image binds `0.0.0.0:10000`; Render supplies `PORT`. For this public Render service, enable `TRUST_PROXY=1`: visitor quotas trust only the Cloudflare-overwritten `CF-Connecting-IP` header, not `X-Forwarded-For`. Invalid/missing values share an unknown bucket; IPv6 addresses share their /64 and IPv4-mapped IPv6 uses the IPv4 bucket. The final `X-Forwarded-Proto` scheme handles TLS termination for the same-origin check. Keep trust off for direct hosting or any proxy without these guarantees. See [Render’s client-IP guidance](https://render.com/articles/host-pocketbase-on-render). Verify the actual limit and isolation using independent public clients.
5. Deploy manually. Match the build’s exact commit to the reviewed public release SHA. Leave `GIT_SHA` unset so health reports the host’s `RENDER_GIT_COMMIT`; an arbitrary override is not deployment proof. Confirm `/api/health` reports the expected SHA and live/real-model configuration.
6. Verify one complete real Qloo and Groq flow: artist identities, three partner categories, supported claims and exact receipts, real writer and baseline, exports with no extra Qloo calls, cancellation/errors and desktop/mobile. Any scripted/template fallback fails full acceptance. Verify progressive SSE through the real proxy, actual client rate-limit isolation, and a measured cold start after genuine idle spin-down. Health alone does not prove these behaviors.

Free hosting and shared provider quotas constrain availability. Groq may require a quota wait during writing or the baseline; waits remain bounded by each model-call timeout and caller cancellation. Do not infer visitor capacity from one successful run. Runs are in memory and disappear on restart; ephemeral caches may also disappear. Do not enter confidential booking inputs. Review [privacy](../PRIVACY.md) and the providers’ applicable terms before using the demo.

Record the final source SHA, public URL, actual hosted results, observed cold start and known limits in a release receipt. The hackathon has ended; deployment is a portfolio release and does not establish a hackathon submission.
